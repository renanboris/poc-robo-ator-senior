# Requirements Document

## Introduction

The Lego Builder module (`lego_builder.py`) is responsible for extracting reusable technical actions from saved training scripts (`roteiros_salvos/`) to build the action library (`biblioteca_acoes.json`). Currently, the display output is verbose and could be optimized for better readability while maintaining usefulness for debugging and monitoring.

## Glossary

- **Lego_Builder**: The module `lego_builder.py` that extracts technical actions from saved training scripts
- **Roteiro**: A structured training script containing metadata, recording configuration, and steps with technical actions
- **Ação_Técnica**: A technical action within a roteiro step, containing semantic intent, target element, and execution details
- **Biblioteca_de_Ações**: The action library file (`biblioteca_acoes.json`) containing unique technical actions extracted from all roteiros
- **Display_Output**: The console/log output generated by the Lego_Builder during execution
- **Verbose_Mode**: Detailed logging level showing individual action processing
- **Concise_Mode**: Optimized logging level showing only essential information

## Requirements

### Requirement 1: Optimize Display Separators

**User Story:** As a developer, I want cleaner visual separators in the Lego_Builder output, so that I can quickly identify different sections without excessive visual noise.

#### Acceptance Criteria

1. WHEN the Lego_Builder starts execution, THE Display_Output SHALL show a concise header with version and timestamp
2. THE Display_Output SHALL use moderate-length separators (30-40 characters) instead of 50-character lines
3. THE Display_Output SHALL maintain clear visual distinction between sections
4. THE Display_Output SHALL preserve the ability to visually parse progress stages

### Requirement 2: Consolidate Progress Reporting

**User Story:** As an operator, I want consolidated progress information, so that I can monitor execution without being overwhelmed by individual action logs.

#### Acceptance Criteria

1. WHILE processing roteiros, THE Display_Output SHALL show batch progress updates (e.g., "Processed 10/25 roteiros") instead of individual file processing messages
2. WHEN new unique actions are found, THE Display_Output SHALL show summary counts instead of individual "Peça catalogada" messages in normal mode
3. WHERE verbose mode is enabled, THE Display_Output SHALL show individual action logging for debugging purposes
4. THE Display_Output SHALL maintain real-time progress indication for long-running operations

### Requirement 3: Optimize Summary Statistics

**User Story:** As a user reviewing execution results, I want clear, consolidated summary statistics, so that I can quickly understand the outcome without parsing multiple lines.

#### Acceptance Criteria

1. WHEN Lego_Builder completes successfully, THE Display_Output SHALL present a single consolidated summary block
2. THE Summary_Block SHALL include all essential statistics: roteiros processed, total actions found, new unique actions added, file location, and version
3. THE Summary_Block SHALL highlight critical information (errors, warnings) prominently
4. THE Summary_Output SHALL maintain machine-readable structure for API consumption

### Requirement 4: Maintain Debugging Capability

**User Story:** As a developer debugging issues, I want access to detailed logging when needed, so that I can troubleshoot problems without cluttering normal operation.

#### Acceptance Criteria

1. WHERE verbose logging is requested (via parameter or environment), THE Lego_Builder SHALL output detailed individual action processing
2. WHEN errors occur during processing, THE Display_Output SHALL show detailed error information regardless of verbosity level
3. THE Verbose_Mode SHALL include all information currently available in the existing implementation
4. THE Default_Mode SHALL be optimized for conciseness while preserving usefulness

### Requirement 5: Preserve API Compatibility

**User Story:** As an API consumer, I want consistent return values, so that my integrations continue to work after display optimizations.

#### Acceptance Criteria

1. THE Lego_Builder SHALL maintain the exact same return dictionary structure
2. ALL existing fields in the return dictionary SHALL remain unchanged
3. THE Display_Output optimizations SHALL not affect programmatic consumption of results
4. WHEN called programmatically, THE Lego_Builder SHALL return the same data structure regardless of display optimizations

### Requirement 6: Implement Configurable Verbosity

**User Story:** As a system administrator, I want configurable verbosity levels, so that I can adjust logging based on operational needs.

#### Acceptance Criteria

1. THE Lego_Builder SHALL support at least two verbosity levels: concise (default) and verbose
2. THE Verbosity_Level SHALL be configurable via function parameter
3. THE Verbosity_Level SHALL be configurable via environment variable
4. THE Default_Verbosity SHALL be concise mode for normal operation
5. WHEN running in CLI mode, THE Verbosity_Level SHALL be configurable via command-line argument
